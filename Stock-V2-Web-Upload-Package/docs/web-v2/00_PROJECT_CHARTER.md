# Stock V2.0 网页版项目章程

- 原项目：股票价值投资财报分析软件 V1.0（Windows 11）
- GitHub：`JulyWorkshop/Stock-V1.0`
- 开发分支：`web-v2-validation`
- 当前阶段：需求基线修订完成；技术架构待最终确认
- 文档状态：业务范围以用户截至2026-11-10的最新明确决定为准

## 1. 项目目标

把现有股票价值投资财报分析软件迁移为可通过公开网址访问的浏览器应用。用户打开网页，导入同一家上市公司多年的年报PDF，完成数据提取、人工确认、财务真实性检测和18步分析，直接在网页中查看完整结果。

网页版的界面、人机交互和分析结果展示，应尽量与 Windows V1.0 保持一致。产品定位仍为上市公司财务体检工具，不荐股、不预测股价、不替用户作投资决策。

## 2. 已确认产品原则

1. 公开网址访问，免注册、免登录。
2. 完全免安装；用户只需打开网页。
3. 首次联网下载网页和计算资源；缓存完成后目标为断网仍可打开并使用。
4. 用户PDF、财务数据、人工修正数据和分析结果全部在用户自己的浏览器设备内处理，不上传服务器。
5. 不建设云端财务计算服务、云数据库或云文件存储；优先采用Cloudflare Pages静态托管。
6. 不加入AI、在线API、行情、估值、买卖建议、自动选股、新闻或舆情功能。
7. 相同输入和相同规则版本必须产生相同结果；结论可追溯。
8. 以当前Windows V1.0实际界面和交互作为迁移基准。
9. 导入支持一次多选和分批添加多份PDF；一个分析批次只对应同一家上市公司。
10. 原Windows软件已有功能和原需求说明书明确要求的分析功能，均属于网页版最终交付范围，不得擅自删减。
11. 分析结果只在浏览器中完整展示，不提供Excel/PDF报告导出。
12. 未识别科目继续按0参与计算，保持当前既定计算口径。
13. 不做项目库、自动保存、历史项目恢复或原始PDF长期留存。

## 3. 用户使用流程

打开网址 → 导入多份年报PDF → 检查公司和年份 → 提取三大财务报表及非财务信息 → 数据校验 → 数据确认/人工修正 → 确认并开始分析 → 在网页查看企业体检总览、真实性检测、18步详细分析、趋势和证据。

项目和分析数据只在当前浏览器会话内存中保留。刷新、关闭标签页或离开后不承诺恢复。离线缓存只缓存网站程序资源，不缓存用户PDF或财务结果。

## 4. 适用范围

- A股非金融类一般工商企业。
- 同一家上市公司连续多年的正式年度报告PDF。
- 建议至少3年，推荐5—10年。
- 优先支持可搜索文字的PDF；扫描版或无法可靠读取的文件应明确提示，不调用在线OCR。

## 5. 五个主页面

以当前 `app/ui/main_window.py` 实际创建顺序为准：

1. 导入年报
2. 数据确认
3. 企业体检总览
4. 财务真实性检测
5. 18步详细分析

原需求说明书第44节的页面4/5顺序与当前Windows源代码不同。用户已确认以当前Windows实际界面顺序为迁移基准。

Web版增加流程门控：未导入项目不能进入后续页面；数据确认完成前不能进入正式分析页面。

## 6. 迁移原则

- 优先复用原有Python PDF解析、数据模型、计算公式、规则引擎和 `rules.json`。
- PySide6桌面界面改为浏览器UI，不机械搬运桌面专属依赖。
- 原需求书中尚未在当前代码实现的非财务信息提取、完整指标覆盖等功能，仍属于必须完成的目标范围。
- 先验证解析和计算结果，再逐页迁移UI。
- 不得用演示数据冒充真实分析结果。
- 不得为了网页适配而静默改变公式、阈值或科目口径。
- 不开发Excel/PDF报告生成和下载。
- 所有已知差异、未实现项和测试结果必须如实记录。

## 7. 阶段审批

按用户要求的开发SOP推进：需求基线 → 产品/技术架构 → 开发计划 → 分阶段开发 → 测试验收 → 发布维护。阶段方案提交用户审批后再实施。每次会话结束和更换AI前更新状态与交接文档。
