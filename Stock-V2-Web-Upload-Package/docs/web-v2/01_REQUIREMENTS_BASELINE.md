# Stock V2.0 网页版需求基线

状态：用户已确认关键产品决定。本文覆盖原需求书中与最新决定冲突的报告导出要求。

## 1. 已确认产品决定

| 事项 | 决定 |
|---|---|
| 访问方式 | 公开网址、免注册、免登录 |
| 安装方式 | 完全免安装 |
| 首次使用 | 联网加载网页和计算资源 |
| 离线使用 | 资源缓存后目标为断网可用 |
| 数据处理 | 全部在用户浏览器本机完成，不上传PDF、财务数据或分析结果 |
| 云服务 | 不建设云计算、云数据库或云文件存储；静态托管优先 |
| 项目自动保存 | 不需要 |
| 历史项目恢复 | 不需要 |
| 原始PDF长期留存 | 不需要 |
| 结果查看 | 完整结果直接在浏览器页面展示，交互逻辑尽量与Windows软件一致 |
| Excel/PDF导出 | 明确取消，不开发下载功能 |
| 非财务信息提取 | 必须保留原需求 |
| 未识别科目 | 按0计算，延续当前既定口径 |
| 功能范围 | 原Windows软件已有功能 + 原需求说明书明确要求的分析功能，网页版均须覆盖；报告导出除外 |

## 2. 用户操作流程

打开网址 → 新建一次性分析 → 一次多选或分批添加多份年报PDF → 检查公司和年份 → 解析三大财务报表及非财务信息 → 单位统一 → 数据勾稽校验 → 数据确认和人工修正 → 用户确认后开始分析 → 网页展示总览、真实性检测、18步详细分析、趋势图和证据。

PDF字节、解析数据、修正值和分析结果只在当前浏览器会话内存中保留。刷新或关闭后不承诺恢复。不建立项目库、IndexedDB历史档案或PDF长期存储。离线缓存仅用于程序资源。

## 3. 功能范围

### 3.1 PDF导入与文件检查
- 多文件选择、拖拽和分批添加。
- 文件名、公司名称、股票代码、年度和解析状态显示。
- 检查是否为年度报告、是否同一家公司、年份识别、缺失年份、重复年份、PDF可读性。
- 支持移除文件、清空本次导入列表。
- 扫描版/不可可靠读取PDF明确提示，不调用在线OCR。

### 3.2 三大财务报表提取
- 合并资产负债表、合并利润表、合并现金流量表。
- 保留原有科目别名、单位识别、表格解析、文本回退和补漏策略。
- 保存公司、年度、报表类型、科目、原始数值、单位、统一数值、来源PDF名称和页码。
- 未识别科目按0参与计算；数据确认页仍须标记识别状态，不能把“程序未识别后按0处理”和“年报原文明确为0”混为一谈。

### 3.3 非财务年报信息提取（必须实现）
按原需求书第12节，使用固定标题、关键词和规则，不使用AI：
- 重要提示：审计意见类型、现金分红方案。
- 公司业务概要：主营业务范围、主要产品、行业地位、市场占有率、六类核心竞争力。
- 经营情况讨论与分析：主营业务分析、分行业/产品/地区、产销量、成本、前五大客户/供应商、期间费用、研发费用化/资本化、现金流变化、非主营业务利润影响、资产负债变动、行业经营信息、投资、资产/股权出售、控股参股公司、结构化主体、未来发展。
- 重要事项：原需求书列出的18类事项，重点包括资金占用、审计意见说明、会计政策变更、诉讼、处罚、诚信、关联交易、重大合同等。
- 普通股股份变动及股东情况：大股东/核心团队增减持、股票质押、实际控制人持股比例。
- 董事监事高管和员工情况：核心团队持股与薪酬、离职、工作经历、员工人数变化、人均薪酬。
- 与18步配合的非财报检查项：大股东质押、实际控制人持股、前五大客户/供应商占比、现金分红政策、员工人数变化、人均薪酬、重大资产负债变动、研发投入费用化/资本化。

### 3.4 单位识别与科目兼容
- 按原需求书第13、14节识别报表单位并统一。
- 兼容不同年度年报中的科目名称变化和别名。
- 单位、科目映射必须可追溯，不得猜测无法识别的数据。

### 3.5 数据校验与确认
- 执行资产负债、利润、现金流等勾稽检查。
- 显示财务数据确认表，支持三大报表切换。
- 用户可以人工修改任意单元格。
- 保留PDF原始识别值、用户修正值和恢复原始值功能。
- 修改项有明显标识。
- 点击“确认数据并开始分析”后才进入正式分析。

### 3.6 财务真实性/造假风险检测
必须覆盖原需求书第19—29节，包括：
- 应收账款及合同资产占总资产、收入增速关系提示。
- 现金利息收益率。
- 高货币资金、高有息负债、高利息支出组合。
- 预付款项占比、预付款+其他应收款占比。
- 固定资产+在建工程占比、短期变化及与应收/存货组合检查。
- 毛利率水平和波动。
- 收现比、净现比及5年平均。
- 关联交易次数、金额和连续性。
- 五类审计意见识别及重大可靠性风险提示。
- 不得将风险信号表述为已证明公司造假。

### 3.7 18步分析及全部补充指标
- 按原需求书第31—32节完整实现18步，不得只实现现有规则表中的少数指标。
- 保留每一步的原始名称、顺序、科目口径、公式、阈值、解释和课程出处。
- 纳入原需求书第32节全部补充指标：经营相关资产、优质资产、货币资金/交易性金融资产、应收、预付、存货、商誉、在建工程、固定资产、无形资产、总资产增长、主业收入占比、毛利率、期间费用率、销售费用率、主营利润、主营利润率、主营利润/营业利润、营业利润、利润总额、净利润、每股收益、营业外收入净额、汇兑/套期/公允价值收益、其他收益/投资收益/资产处置收益等、ROE、归母净利润增长、收现比、净现比、经营现金流、资本开支现金比、分红现金比、现金净增加额和三大活动现金流类型。
- 对原资料未明确给出阈值的项目，只显示数值和趋势，不自行创造阈值。
- 删除原课程中的同行业比较部分，不新增同行比较。

### 3.8 评价、趋势和图表
- 不使用单一综合总分。
- 逐项评价，体现优势程度和风险程度。
- 统一状态：优势、一般/正常、需要关注、高风险。
- 展示最新值、3年变化、5年平均、5年最高/最低、适用时的CAGR、同比和连续增长/下降年数。
- 核心趋势图包括总资产、营业收入、归母净利润、ROE、毛利率、经营现金流、应收占比、有息负债、商誉占比、固定资产+在建工程占比。
- 总览页展示主要优势、关注项和高风险。

### 3.9 结果证据与浏览器展示
- 分析结果必须直接在网页中完整展示，不要求用户下载文件才能查看。
- 点击结论可展开年度数据、计算依据、参考区间、公式和原始来源。
- 显示PDF文件名及原文页码。
- 结果明确区分程序识别值与用户修正值。
- 企业体检总览、真实性检测、18步分析和非财务信息应在网页内有清晰入口。
- 不开发Excel导出、PDF报告生成、报告下载按钮或其他报告文件导出功能。

## 4. 五个主页面

以当前 `app/ui/main_window.py` 实际顺序为准：
1. 导入年报
2. 数据确认
3. 企业体检总览
4. 财务真实性检测
5. 18步详细分析

## 5. 明确禁止
AI分析/总结/问答；在线API；上传PDF；股票行情、K线、技术分析；估值、PE/PB历史百分位、DCF；同行业比较、行业平均、行业排名；自动选股、股票推荐、买卖建议；仓位管理、投资组合；新闻和舆情；Excel/PDF报告导出。

## 6. 非功能要求
- 完全本机处理；网络只用于下载静态网站资源。
- 离线缓存不保存用户数据。
- 同样输入、修正值、规则版本，结果完全一致。
- 数据来源、公式、阈值、结论可追溯。
- 缺失/异常情况给出明确提示。
- 解析与计算放入Web Worker，避免阻塞界面。
- 目标首轮环境：Windows 11 Chrome/Edge；最低版本待技术方案阶段确认。

## 7. 对原需求书的变更说明
原需求书第四十五节“结果导出”中的Excel和PDF导出，已被用户在2026-11-10明确取消。该项不再属于网页版需求，也不列为开发任务或验收项。其余分析功能要求仍然保留。
