## 2. 成熟依赖候选与许可初查

| 项目 | 用途 | 已查许可证 | 备注 |
|---|---|---|---|
| Vue 3 | UI框架 | MIT | 候选 |
| Vite | 构建工具 | MIT | 候选 |
| vite-plugin-pwa | PWA/Service Worker | MIT | 候选 |
| Pyodide | 浏览器内Python/WASM | MPL-2.0 | 用户本机基础加载已验证 |
| Mozilla PDF.js | PDF读取/文本提取备选 | Apache-2.0 | 可作为PyMuPDF许可替代路线评估 |

## 3. 重要许可证风险
PyMuPDF仓库`COPYING`为AGPL v3。公开部署浏览器端WASM前，必须审查AGPL对分发、源代码提供和修改版本的适用要求；必要时获取商业许可或专业法律意见。静态托管和本机处理本身不能自动消除许可义务。

## 4. 推荐架构（待审批）
- 前端：Vue 3 + TypeScript + Vite，复刻Windows现有五页面操作逻辑。
- 后台任务：Web Worker处理PDF解析和规则计算，避免界面冻结。
- 业务计算：优先复用原Python解析、公式、规则和数据模型。
- Python运行时：Pyodide作为候选运行时。
- PDF引擎：先解决PyMuPDF许可；如无法满足，评估Mozilla PDF.js替代路线，并重新验证表格解析准确率。
- 数据生命周期：PDF字节、解析数据、人工修正和结果只在当前浏览器运行内存中；不使用IndexedDB/localStorage保存项目。
- 结果展示：所有分析结果直接在浏览器页面显示，不生成或下载Excel/PDF报告。
- 离线：Service Worker只缓存网站、Worker、Python运行时和依赖资源，不缓存用户PDF或分析数据。
- 部署：Cloudflare Pages静态托管；不建设财务数据API、云数据库或云文件存储。
- 隐私：禁止遥测、埋点和第三方分析脚本；网络请求仅允许静态资源和版本资源下载。

## 5. 推荐数据流
浏览器选择PDF → 文件字节传入本机Worker → Worker/Python运行时解析三大报表和非财务信息 → 返回结构化数据 → 网页数据确认与人工修正 → 用户点击确认 → Worker执行原规则/公式 → 网页展示总览、真实性检测、18步、趋势和证据。

任何步骤都不把PDF、科目数据、人工修正或分析结果发送到网站服务器。

## 6. 关键风险
- PyMuPDF许可证必须解决，或采用合规替代方案。
- 不能假定所有Python依赖均可安装到Pyodide，需按实际import逐个验证。
- 非财务信息提取必须按原需求书实现固定标题、关键词、表格和来源页码识别，不使用AI。
- 多PDF内存占用、Worker进度、失败恢复和大文件性能需真实测试。
- 浏览器刷新/关闭后不承诺恢复，页面需在适当位置提示当前分析仅在本次会话有效。

## 7. 开发顺序建议
1. Vue/Vite工程骨架、五页面导航、流程门控。
2. Worker + Pyodide启动、离线静态资源缓存。
3. PDF导入、文件校验和多文件队列。
4. 三大报表解析与Windows结果对照。
5. 非财务信息提取。
6. 数据确认、人工修正、勾稽检查。
7. 完整真实性规则和18步全部指标。
8. 总览、趋势图、证据追溯。
9. 离线、隐私、确定性、性能和兼容性验收。
10. 处理许可证后部署Cloudflare Pages。
