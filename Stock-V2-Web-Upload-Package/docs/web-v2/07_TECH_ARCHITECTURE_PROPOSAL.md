# Stock V2.0 网页版技术架构方案（修订审批稿）

状态：用户已要求直接进入正式网页开发；本稿按Vue/Vite、Worker、Pyodide、本机数据流、PWA缓存和取消导出方向实施。PyMuPDF许可证仍是公开发布前的阻断事项。

## 1. 总体架构
采用纯静态网站 + 浏览器本机计算：
- 静态网站：Cloudflare Pages。
- UI：Vue 3 + TypeScript + Vite。
- 后台任务：Web Worker。
- 业务计算：优先复用原Python解析、公式、规则和数据模型。
- Python运行时：Pyodide（用户本机已完成基础加载验证）。
- PDF引擎：PyMuPDF为当前验证路线，但必须先解决AGPL许可；如无法满足，评估Mozilla PDF.js并重新验证表格解析准确率。
- 本机数据：仅当前浏览器会话内存，不做IndexedDB/localStorage持久化。
- 结果展示：完整分析结果直接在浏览器页面呈现；不生成或下载Excel/PDF报告。
- 离线：Service Worker只缓存网站和计算引擎资源。

## 2. 运行数据流
1. 用户选择多份PDF。
2. 浏览器读取文件字节，传入本机Worker。
3. Worker调用Python/PDF解析模块，提取三大报表和非财务信息。
4. 将结构化数据返回网页。
5. 用户在数据确认页检查和修正。
6. 用户点击确认后，Worker执行勾稽检查、真实性检测和18步分析。
7. 网页展示总览、风险、趋势、18步指标、非财务信息和来源证据。
8. 用户在浏览器中直接查看全部结果；没有报告导出步骤。

任何步骤都不把PDF、财务数据、人工修正或分析结果发送到网站服务器。

## 3. 数据生命周期
- 文件只在用户当前页面会话中处理。
- 不使用项目数据库、历史记录、自动保存或PDF长期存储。
- 刷新/关闭页面后不承诺恢复。
- 可在导入页和结果页提示“本次分析仅在当前页面会话中保留，请在离开前完成查看”。
- Service Worker不得缓存用户文件或分析数据。

## 4. 隐私与网络约束
允许网络请求：
- 首次加载HTML/CSS/JS。
- 下载Pyodide、PDF引擎、Worker及静态依赖。
- 可选的静态版本更新检查（不含用户数据）。

禁止：
- PDF上传。
- 财务数据/分析结果上传。
- 遥测、用户行为埋点、第三方分析脚本。
- 在线OCR、云端Python、云数据库或文件存储。

验收时使用浏览器开发者工具检查Network请求，确认没有用户数据请求。

## 5. 许可证风险
PyMuPDF仓库`COPYING`为AGPL v3。公开部署浏览器端WASM前必须审查许可义务；可选路径为获取商业许可、按合规要求履行AGPL义务，或评估PDF.js替代。不能因静态托管和本机处理就推断没有许可义务。

## 6. 关键风险
- PyMuPDF许可证必须解决，或采用合规替代方案。
- 不能假定所有Python依赖均可安装到Pyodide，需按实际import逐个验证。
- 非财务信息提取必须按原需求书实现固定标题、关键词、表格和来源页码识别，不使用AI。
- 多PDF内存占用、Worker进度、失败恢复和大文件性能需真实测试。
- 浏览器刷新/关闭后不承诺恢复，页面需提示本次会话有效。

## 7. 开发顺序建议
1. Vue/Vite工程骨架、五页面导航、流程门控。
2. Worker + Pyodide启动、离线静态资源缓存。
3. PDF导入、文件校验和多文件队列。
4. 三大报表解析与Windows结果对照。
5. 非财务信息提取。
6. 数据确认、人工修正、勾稽检查。
7. 完整真实性规则和18步全部指标。
8. 总览、趋势图、证据追溯。
9. 离线、隐私、确定性、性能和兼容性验收。
10. 处理许可证后部署Cloudflare Pages。

## 8. 本次范围变更
原架构稿中Excel/PDF导出模块及其依赖已删除。网页只展示结果，不提供文件导出。
